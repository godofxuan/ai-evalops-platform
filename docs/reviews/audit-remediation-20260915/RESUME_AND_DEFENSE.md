# 可直接使用的项目介绍、简历与答辩

只使用 CLOSEOUT_RESULTS.md 和交付回执证实的身份/结果。新代码未获远端 CI 成功前，不写“最新版本 CI 全绿”。用户本人是否理解与能亲自复现需要练习，工具执行通过不能替代个人掌握。

## 项目介绍（约一分钟）

我做的是 AI 评测任务的后端基础设施，不是又训练了一个大模型。工程师提交两个被测版本和同一批题目后，平台用 PostgreSQL 管理任务、尝试和结果，worker 执行外部目标，支持超时重试、取消和失联恢复。报告把任务是否完成、质量是否达标、证据是否足够分开，并能导出离线复核。

最有价值的部分是失败后的可信性：外部请求可能重复，但过期 worker 不能覆盖新结果；无效引用和矛盾终态不会悄悄变成好分数；失败不能从分母消失。本轮通过真实数据库锁等待复现租约和死锁问题，再修复，并用40项合成故障演练验证整个持久路径。公开四模型比较是另一条历史实验线，不能拿它冒充平台可靠性或模型效果提升。

## 面试问答

**为什么不是直接用一个评测框架？**

现有框架擅长 evaluator 和数据集。这个项目练习的是长任务的可靠执行、租户/权限边界、版本化观察、失败分母与证据交付；可以接现有 evaluator，而非声称在全部评测能力上替代成熟开源项目。

**exactly-once 做到了吗？**

没有外部 exactly-once。worker 在收到 HTTP 返回后、提交前崩溃，恢复会再次调用目标。平台只对合法 attempt 的结果唯一接纳，attempt/call ledger 不隐藏重复成本。39次请求与24个 accepted 是直接证据。

**为什么 UPDATE WHERE 有 expiry 条件还不够？**

原程序在等待数据库锁之前取应用时间。等获得锁时那个时间已过时，条件仍可满足。新程序先锁决策所需行，再读 clock_timestamp；保留 owner、version、status、严格 expiry。不能用事务开始时间 now()。

**SKIP LOCKED 是否等于公平？**

不是。它避免等待锁，不保证公平。本项目另有既有租户公平状态与对应回归。claim 持 Job 后遇到父 Run 时只允许非阻塞 admission，繁忙则退让；普通 Run 的 outbox FK 也可能偷偷取得父锁，所以必须复现并防护。

**怎么证明修复而非改测试？**

保留真实PG red日志，固定屏障观察实际等待与服务器时间跨 expiry；修复后同输入通过，wrong owner/version和等号控制仍拒绝。reaper/commit固定竞态重复20次。未把测试通过推导为所有时序数学证明。

**引用正确率是什么？**

这里只核来源 ID。目标引用所有gold还多报错误来源时，recall可以1但precision低于1。冲突 source_id/id 是非法观察，不选有利的键。semantic_support 未实现。历史完整 scorer 曾覆盖注册函数分数，因此解释反例时必须说明实际调用路径。

**为什么合成实验最后是 EXECUTION_FAILED？**

预设故障本来就要求12项失败、4项取消。平台通过是它正确计账、拒绝不合法提交、可恢复并重算；不是把故障任务说成模型质量通过。

**local/private/public 有什么差别？**

local结构验证不代表重评分；提供原始数据给 load_evidence/analyze 才完整重算。durable private有原输入与观察可重算，public只有投影。hash自洽不等于数据来源可信，更不是生产或人评资格。

**还欠缺什么？**

本轮没有正式业务 A/B、人评、Shadow 或生产验收。历史调度 NEGATIVE_SCALING 没有被本轮修复抵消。本机 Windows 便携服务验证不是 Linux Compose/MinIO 等价验收。额外DB锁/时钟读取的吞吐影响需独立冻结基准再判断，不能预设提速。
